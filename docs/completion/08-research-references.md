## What I did not adopt, and why

| Option | Why not now |
|---|---|
| Split the API into services, or add a message broker (SQS, RabbitMQ, BullMQ) | One practice, tens of requests per minute; Postgres tables already work as durable queues with row locks. A broker adds a second source of truth and another processor needing a DPA (ADR-0001, ADR-0002) |
| Kubernetes or AWS (ECS, RDS, KMS) | Owner chose Render (decision #19) and approved a small budget (D-10). The old docs that described AWS were inaccurate (V-04) |
| Replacing Express or Prisma | Both are supported and well tested here; Prisma 7 and Express 5 are upgrades to schedule, not replacements |
| Multi-region or active-active | RTO of hours is acceptable for a dental practice that can fall back to phone bookings (ADR-0003) |
